# Furniture photo search

This integration adapts [Shreya's six photo-search files](https://github.com/shreya-sneha-dhakal/pixel-perfect-replica/tree/57e756b6bc0daa5f043ada909f07035ad2e0ca43/src) from commit `57e756b6bc0daa5f043ada909f07035ad2e0ca43` into the existing **Vite React SPA**. It does not import TanStack Start or its server functions. Angelo's rendering, placement callbacks, fit rules, and Furney's product interfaces are unchanged.

## What works without AI credentials

Open **Search by Photo** beside the catalog search box. Its bounded popover leaves the room layout intact; Close or Escape dismisses it and returns focus to the trigger. **Manual search (no AI)** always works: choose category/style, then Find matches. The results are ranked by Shreya's category-first rules and optional color/material/style/keyword weights over the existing products passed from `PlannerProvider`. Visual attributes remain separate in `src/data/furnitureAttributes.ts`.

Results retain the actual `FurnitureProduct` object. Add to Room sends its original product ID to the existing `onAddProduct` callback, creating a shared `placedItems` instance rendered by the unchanged 3D planner. Dimensions in meters, prices, retailer links, collision warnings, and totals remain sourced from the integrated catalog. No products, dimensions, prices, cart, or placements are generated by AI.

Uploading without a configured key produces an explicit `not_configured` error, not an invented classification. Manual results are labeled **Manual search — no photo was analyzed**. The ordinary catalog's query, category filters, and price sort remain independent and intact.

## Enable real OpenAI analysis locally

1. Use Node 22.12+ (Node 24 recommended). Install with `npm ci`.
2. Copy `.env.example` to **`.env.local`**, which is ignored by Git.
3. Set a valid, funded OpenAI project API key in `.env.local`:

   ```dotenv
   OPENAI_API_KEY=your-server-side-key
   OPENAI_MODEL=gpt-4.1-mini
   ```

   Never use a `VITE_` prefix, put the key in React code, or commit it. Shreya's `LOVABLE_API_KEY` does not transfer and is not used. `OPENAI_MODEL` is optional; select an accessible model supporting image inputs and strict structured output if changing it.
4. Restart `npm run dev` after setting environment variables. The development-only Vite middleware serves the same `/api/photo-search` handler as production; OpenAI variables are loaded only into the server process. No extra server, database, SDK, or framework is required.
5. Upload a clear photo of a single furniture item. A successful response shows **AI description — please review**, its category/color/material/style, and matching catalog pieces. Treat descriptions as uncertain visual estimates, not proof of material or brand.
6. With the dev server running, run **`npm run test:vision`**. This sends the real local `chair-2.jpg` and `sofa-1.jpg` sample images to the endpoint and requires `Chairs` and `Sofas`, respectively. It exits nonzero on missing credentials, API failure, or incorrect classifications. It is opt-in and can incur OpenAI usage charges; the normal test suite mocks provider transport and does **not** establish AI accuracy.

`npm run preview` serves only the built static SPA, so it has no analysis API. Manual search still works. Use `npm run dev` for local API testing or a Vercel deployment.

## Enable on Vercel

1. Import the **existing `ardianagoes/furney` repository**, select the Vite framework preset, set build command `npm run build`, output directory `dist`, and a supported Node version. Do not create another source repository or migrate the app.
2. Add `OPENAI_API_KEY` in the Vercel project's **Settings → Environment Variables** for the intended Preview/Production environment. Optionally add `OPENAI_MODEL`. Keep these server-side; no `VITE_` versions are needed.
3. Deploy/redeploy the intended branch after configuring the variables. Vercel discovers `api/photo-search.ts` as the Node function for `/api/photo-search`. Do not rewrite `/api/*` to `index.html` if adding SPA rewrites later.
4. Run the real smoke test against that deployment by setting `PHOTO_SEARCH_BASE_URL` before `npm run test:vision` (PowerShell: `$env:PHOTO_SEARCH_BASE_URL = 'https://your-furney-deployment.vercel.app'`). Deployment protection must permit the test client; otherwise test through the signed-in browser.
5. Only report live AI classification as verified after both actual chair and sofa requests succeed. Then test Add to Room from a result and confirm it appears in the existing 3D room with the correct price/dimensions.

The implementation targets the [OpenAI Responses image-input API](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses) with [structured output](https://developers.openai.com/api/docs/guides/structured-outputs). The default [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) supports these capabilities. The API host is fixed to `api.openai.com`; users cannot supply upstream URLs or models through an upload request.

## Validation, limits, and privacy

- JPG, PNG, and WebP only; nonempty files up to **3 MiB**. The source's 5 MB cap is reduced because base64 expands JSON payloads, while [Vercel function bodies are limited to 4.5 MB](https://vercel.com/docs/functions/limitations).
- The server checks JSON/body length, base64 validity, decoded bytes, MIME type, and JPEG/PNG/WebP signatures. Remote image URLs, SVGs, and arbitrary uploads are rejected before contacting OpenAI.
- POST with JSON only. Cross-origin browser requests are rejected. Local rate limits use the socket address; Vercel uses its platform-provided `x-vercel-forwarded-for` header.
- Basic limits: **5 requests per caller per minute, 20 total per minute per warm function instance**. Counters retain only hashed caller identifiers/counts/expiry, never images. Serverless instances do not share counters: add a deployment-level Vercel Firewall rule or shared rate-limit service for a strict distributed production quota. The current bounded in-memory limiter is burst protection, not a global spend cap.
- Provider calls time out after 20 seconds. Invalid uploads, missing configuration, rate limiting, non-furniture photos, provider errors, and malformed results produce meaningful errors and preserve the manual fallback.
- No images are saved to disk, databases, localStorage, or application logs. Photos/data URLs exist transiently in browser/server memory for preview and analysis. Closing/clearing cancels the browser's outstanding request and releases the preview. OpenAI requests use `store: false`; any provider-level retention is governed by the OpenAI account's data policies.
- The frontend imports only types, ranking, attributes, and the relative fetch client. The server adapter and environment variables are not part of `dist`.
